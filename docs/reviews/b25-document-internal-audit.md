# B2.5 DOC-O 内部文档审计

**日期**：2026-09-25  
**范围**：G-OX批准记录、PRD、全局计划、后端计划、目标架构、B2.5计划/验收、追踪矩阵、Draw.io  
**最终结论**：PASS；开放 P0/P1=0。等待人类审核 Draw.io，尚未授权产品代码开发。

## 第一轮：PRD与体验规格审计

检查问题：是否改变已批准主舞台、是否超出V1范围、是否降低首响/打断/资源门、缓存是否改变回答语义。

发现并闭环：

- 将 G-OX 批准边界写入 PRD §2.2 和独立批准记录；前端只允许局部阶段反馈与二级诊断。
- 新增 FR-20，但不把缓存收益冒充普通链性能；AC-04继续只使用普通未命中。
- 天气、记忆、“继续说”和附加语义负例100%强制走正常链；错误命中一次即FAIL。
- RAM≤14GB、VRAM≤22GB、两侧可用≥2GB和打断≤400ms全部保持，无硬门下调。

结论：PASS，无规格扩张或体验回退承诺。

## 第二轮：架构与实施一致性审计

检查问题：代码实体是否真实、依赖方向是否冲突、B2.5是否造成重写、引擎迁移和回滚是否可执行。

发现并闭环：

- 修正旧目标架构中把已存在 `TurnPipeline`、`LiveTalkingAdapter`、Speech server 和 Launcher 标成“新增/阻断”的过期状态；外审后再次以文件存在与Python导入验证确认三者均存在。
- 新增能力位于端口后：`WarmResponsePolicy/Cache`、`RuntimeMetrics` 和引擎 profile；应用层禁止直接 import TensorRT/vLLM/Avatar上游包。
- Qwen、原Cosy adapter和源模型不删除；engine/PCM为可删派生物；禁止双TTS或双LLM常驻。
- 修复阶段顺序死锁：B2.5作为B2出门修复立即前置，通过并回填B2后才能进入B3。
- 架构可探索图 showcase 校验9/9通过，composition错误0、警告0；自动浏览器 visual-check 因Linux Chrome不可用而跳过，未伪报通过，后续使用宿主浏览器人工审查。

结论：PASS，迁移成本受控，分层和语义无冲突。

## 第三轮：验收、防虚假证据与文档完整性审计

检查问题：是否存在三无验收、是否能复跑、是否混淆目标和实测、失败是否能回到计划阶段。

发现并闭环：

- OX-01～12均给出用户场景、操作、证据和量化门槛；普通/命中/失效强制分桶。
- 当前5.08s、CER 0.71%、TTS 2.55/3.43s、FPS 25.006、RAM 13.85GiB、VRAM 9785MiB均保持为B2事实，不写成B2.5成绩。
- 旧G-UX页的76.92%/10.043s明确标为历史失败样本；活动基线文档不再引用其作为当前结论。
- 10份活动Markdown的相对链接检查通过；新Draw.io XML可解析、6页、各页ID/引用完整；未超过8页。
- 停线、回滚、B2回填和“B2.5通过不等于V1完成”均明确。

结论：PASS，无三无验收、无虚假出门路径。
