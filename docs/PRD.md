# PRD：cyberWife V1

**状态**：B0～B5与B2.5工程阶段门、ARCH1、RES1及V1RC1自动化门均已通过；V1FINAL正在关闭人类感知/物理设备取证，干净机独立复现仍为发布外部门
**版本**：1.9
**更新日期**：2026-10-06
**目标平台**：Windows 11 + WSL2，本机原生进程；浏览器完成 V1 验收  
**目标用户**：单一成人用户，私人、非商业使用

## 0. 发布描述

cyberWife 把经明确授权的照片、声音和相处方式留在用户自己的电脑里，形成一个能听、会说、有表情、记得共同经历的私人数字伴侣。用户一次点击即可开始连续语音对话，并能随时插话打断；人物以电影感真人画面存在，而不是以聊天机器人或模型控制台的形式出现。除首次设置、隐私管理和故障恢复外，界面不以技术术语打断陪伴体验。

## 1. 产品目标与成功指标

**北极星指标**：一次 10 分钟对话中，用户不需要处理技术设置，且愿意继续交流的有效陪伴时长。

| 目标 | 可测指标 | V1 出门门槛 |
|---|---|---:|
| 顺利开始 | 首次设置成功率 | 单用户 5/5 次成功 |
| 对话可用 | 20 轮连续语音成功率 | ≥95% |
| 反应自然 | 说完到首响 P95 | ≤7.0s（P50记录但不设硬门） |
| 可以插话 | 用户出声到停止播音 P95 | ≤400ms |
| 画面稳定 | `inferfps` / `finalfps` | 均 ≥25 FPS |
| 长时间可用 | 连续对话运行 | 1 小时无崩溃、OOM、延迟持续累积 |
| 声音可信 | 授权人盲听主观评分 | ≥4/5 |
| 记忆可控 | 已删除内容重新召回率 | 0% |
| 隐私可信 | 核心链不依赖公网；仅本机连接且无联网上传动作 | 白盒扫描与运行期连接采样必须通过 |

指标的环境、样本、操作步骤和证据要求以 [验收计划](acceptance-plan.md) 为准；不得只凭界面演示判定通过。

## 2. 产品原则

1. **人物优先**：默认看到人物与关系状态，不展示模型参数和日志。
2. **一次动作开聊**：主屏唯一高权重操作是语音球。
3. **沉浸但可控**：日常对话沉浸；授权、删除、停止和退出必须明确可控。
4. **本机即边界**：人物素材、声纹、会话、记忆和生成内容不进入公网。
5. **失败可恢复**：错误必须说明影响、给出恢复动作，并保留已完成设置。
6. **真实状态**：未加载、降级和失败不能显示为“就绪”。

### 2.1 G-UX 决议与实现重心

- 用户于 2026-09-24 批准既有交互体验满足 V1 验收；前端体验范围冻结。
- V1 后续工作重点转向后端真实链路、一键生命周期、模型运行时、打断、记忆隐私与可观测性。
- 前端只允许进行后端接线、错误合同适配、可访问性/兼容性回归修复；视觉重构或新增交互必须重新走 G-UX。
- 体验原型与基线见 [`review/cyberwife-v1-experience-review.html`](review/cyberwife-v1-experience-review.html) 和 [`experience-benchmark.md`](experience-benchmark.md)。

### 2.2 G-OX 优化体验决议

- 用户于2026-09-25批准[`review/cyberwife-v1-optimization-review.html`](review/cyberwife-v1-optimization-review.html)的体验边界，随后完成DOC-O审查并授权实际开发。
- 保持人物、主舞台、六态、主操作和既有路由；只允许增加“组织回答/准备声音/降级”等局部反馈与运行状态二级诊断。
- 高频问候可使用严格完整句预热；天气、记忆、“继续说”和任何带附加语义的问候必须进入正常模型链路。
- 缓存命中指标必须与普通未命中分离；普通路径继续独立满足 NFR-01，不得以平均命中率降低硬门。
- B2.5是B2首响阻断的修复分支；B2.5与B2均已通过，当前允许进入B3。里程碑编号不构成绕过阶段门的授权。
- 用户于 2026-09-25 批准 ADR-009：B2.5 签首响/缓存，B2 签 Avatar 恢复，B3 签打断，B5 重跑完整组合；此修正只调整证据归属，不降低任何体验门槛。
- B4 只能使用 B3 已 `e2e_accepted` 的真实 session/turn 开展最终验收；B5 必须先补齐授权撤销、资产版本激活/回退和默认沉浸式入口，再执行总回归。
- “无限多轮”表示产品不设置固定轮数上限，并以100轮压力与1小时真实运行证明无队列、任务、内存或延迟单调增长；不承诺数学意义上的无限运行。

### 2.3 G-LAT7 首响门槛决议

- 用户于 2026-09-25 批准：若进一步优化技术成本过高，V1普通对话首响放宽为P95≤7.0秒；原P50≤2.0秒/P95≤3.5秒门槛由本决议取代。
- P50必须继续如实报告但不作为V1硬门；首响口径、30条普通缓存未命中样本和浏览器首个非静音确认不变。
- 该决议不放宽打断P95≤400ms、音质、资源、稳定性、隐私或离线门槛，也不允许把预热缓存命中混入普通路径。
- 达到7秒门槛后应停止高成本运行时迁移；vLLM/TensorRT-LLM不再是V1必需路线。

## 3. 用户与前提

- 使用者与素材权利人均为成年人；使用者确认获得照片与声音的明确授权。
- V1 是单用户、单角色、私人非商业产品，不提供传播或分享能力。
- 目标机器为 32GB 物理内存、24GB 显存；空闲状态约 16GB 可用内存是正式运行预算，项目源码在 `C:\workSpace\cyberWife`，运行数据在 WSL2 ext4。
- “已下载”不等于“可运行”。所有模型在 B0 完成路径、格式、校验值、许可证和实际加载验证后，才可标记为 `runtime_verified`。

## 4. V1 范围

### 4.1 包含

- 五步首次设置：授权、运行检查、人物、声音、人设。
- 全屏电影感人物主界面；点击开始/结束连续对话。
- 本机 VAD、语音识别、角色回复、声音克隆、口型视频串联。
- 用户说话时终止当前文本生成、音频播放和口型队列，回到监听。
- 实时状态、逐句字幕、可理解的错误与原地恢复。
- 人物、声音、人设的预览、保存、替换与上一版本恢复。
- 近期会话与长期记忆的搜索、编辑、删除和清空。
- “本次不记录”、30 天会话文本保留和自动清理。
- 深色、浅色、跟随系统；键盘操作、焦点和状态播报。
- PowerShell 一键启动/停止/状态检查；所有服务仅监听 loopback。
- 为桌面壳保留 `HostBridge`，为 V2 容器化保留配置与适配器边界。

### 4.2 不包含

- Docker、Docker Compose、镜像构建、容器迁移（归入 V2）。
- 手机或公网访问、外部 STUN/TURN、公网分享链接。
- 摄像头、屏幕读取、电脑操控和常驻唤醒词。
- 多角色、多用户、云同步、主动推送。
- MuseTalk 高画质模式、Tauri/Electron 桌面壳。
- 商业发布、直播、导出传播。

## 5. 核心用户旅程

### J-01 首次设置

1. 用户阅读本地处理说明并确认素材授权；未确认时不能导入真人素材。
2. 系统真实检查 LLM、ASR、TTS、Avatar、Embedding、麦克风、GPU 和磁盘。
3. 用户导入并裁切照片，预览待机人物；也可使用占位素材继续。
4. 用户导入 5–15 秒参考音频和逐字稿，生成试听；也可稍后设置。
5. 用户填写名称、称呼、关系背景、性格和示例对话。
6. 保存配置并进入主屏；失败时保留已完成步骤和输入。

### J-02 日常对话与插话

1. 主屏显示人物、问候和“开始对话”。
2. 点击后进入持续监听；声音波形反映真实输入音量。
3. 静音结束触发识别；字幕先显示用户文本，再流式显示角色回答。
4. 首个可播分句生成后开始 TTS 和口型播放，其余分句继续流水线处理。
5. 用户在角色说话时插话；旧轮次所有下游产物失效，P95 400ms 内静音并回到监听。
6. 用户结束会话；若允许记录，则保存转录并异步提取候选记忆。

### J-03 记忆与隐私控制

1. 用户在设置中搜索、编辑或删除“她记得的事”。
2. 删除单条后立即从检索结果和向量索引移除。
3. 清空全部记忆需二次确认，同时删除源记录、摘要、向量和派生缓存。
4. 开启“本次不记录”后，本次音频不落盘、转录不持久化、长期记忆不写入。
5. 普通会话转录保存 30 天后自动清理；长期记忆保留至用户删除。

### J-04 故障恢复

1. 用户看到“什么不可用、对当前体验有何影响、可以做什么”。
2. 可在原页重试单个服务；不强制刷新或重走首次设置。
3. Avatar 故障时允许降级为静态人物 + 语音；TTS 故障时允许文字回复；LLM、ASR 或麦克风故障时停止语音会话并引导修复。

## 8. 数据、接口与保留策略

- **原始音频**：仅内存/临时流，处理结束立即释放，不进入数据库、日志或崩溃包。
- **会话转录**：SQLite 保存 30 天；“本次不记录”时不写入。
- **长期记忆**：SQLite 事实记录 + FTS5 + `sqlite-vec` 向量，保留到用户删除。
- **人物与声音资产**：存于 WSL2 私有数据目录；以版本引用支持回退，不存 Git。
- **审计事件**：记录授权、编辑、删除、清空、运行恢复的时间和结果，不记录敏感正文。
- **协议**：浏览器与Gateway用REST + WebSocket；Gateway以loopback HTTP向Avatar送PCM，Avatar以loopback WebSocket发送H.264，浏览器用WebCodecs解码；各模型适配器用loopback HTTP/WebSocket或进程IPC。

字段、端点、事件与状态机详见 [目标架构](architecture/target-architecture.md)。

## 9. V1 部署边界

V1 采用“Windows 浏览器 + Windows llama.cpp + WSL2 应用服务”的本机原生部署：

- Windows：浏览器、`RuntimeLauncher.ps1`、`llama-server`（默认 `127.0.0.1:8090`）。
- WSL2：App Gateway（7860）、Speech Worker（8091）、LiveTalking/Wav2Lip（8010）、SQLite/向量索引和私有资产。
- 禁止把 Docker 作为 V1 安装、启动、测试或验收前提。
- V1 必须把端口、模型路径、数据路径、设备和模型适配器外置配置，给 V2 容器化留下可迁移边界。

## 10. 风险与应对

| 风险 | 可能性/影响 | 触发信号 | V1 应对与停线条件 |
|---|---|---|---|
| 多模型并发 OOM | 中/高 | VRAM>22GB、CUDA OOM | 降 ASR 计算类型→缩小 LLM 上下文/层数；仍失败则阻止发布。 |
| WSL↔Windows 网络波动 | 中/高 | 健康检查间歇失败 | 启动时解析主机地址并探测；回退配置必须可用；连续 3 次失败进入 error。 |
| 口型抖动/鬼影 | 中/中 | FPS<25 或主观不自然 | 限制底图规格、队列背压；可降级静态人物，不伪报正常。 |
| 声音克隆漂移 | 中/高 | 相似度<4/5 | Base 模型、干净样本、准确逐字稿；不合格不得通过。 |
| CosyVoice 默认轨回退 | 高/中 | CER>5%、全链P95>7秒或资源越门 | 立即切回保留的 Qwen profile；不得双常驻；按 ADR-008 重新审查默认轨。 |
| 加速引擎版本耦合 | 中/高 | engine反序列化失败、输出漂移或无净收益 | 以端口隔离、固定版本和可删engine控制；失败回退原adapter，不双常驻。 |
| 问候缓存错误命中 | 中/高 | 天气/记忆/附加语义直接播放固定回答 | 仅完整句白名单+完整版本键；负例100%未命中，否则关闭缓存并停线。 |
| VAD 抢答/漏话 | 高/中 | 误打断或长等待 | 用户可理解的响应速度档位；用固定语料调阈值并留证据。 |
| 记忆写入错误 | 中/高 | 错误事实被召回 | 低置信度不固化；来源可追溯；编辑/删除后重建索引。 |
| 模型文件实际不可用 | 中/高 | 路径存在但加载失败 | B0 实际加载和 functional probe；状态保持“待核验”，不得进入 B1。 |
| 许可证偏离 | 高/高 | 商用/传播需求出现 | V1 停止扩围，先替换或获得许可。 |

## 11. 发布与变更控制

- PRD、架构、原型规格、追踪矩阵、里程碑与验收计划共同构成 V1 基线。

- 任何公网依赖、数据上云、商业传播、多用户或 Docker 前移，均视为范围变更。
- V1 的开发出门条件见 [项目计划](project-plan.md)，产品出门条件见 [验收计划](acceptance-plan.md)。
- 2026-09-24 §26 风险接受只继续适用于浏览器本地存储无字段白名单；后续批准重新确立 NFR-04/NFR-06 对后端日志、Git、原始音频、业务数据库和私有资产的发布硬门，逐项对账见 `implementation-contracts.md §34.1`。
