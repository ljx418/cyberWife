# B2.5-O2R 宿主内存修复开发计划

**日期**：2026-09-25  
**状态**：开发前计划已锁定

## 1. 触发原因

用户释放资源后，默认配置重新完成30条真实浏览器链，30/30完整，P50/P95=6.459/8.011秒。启动前 Windows Available=19385MiB；完成后连续采样仅约1284～1430MiB，低于既定2048MiB硬门。与此同时 WSL Available约9.8GiB、VRAM约11.4GiB、swap-in=0。阻断已定位为 Windows llama.cpp/WSL组合常驻，不得直接进入O3扩大运行时。

## 2. 候选与边界

只验证 llama.cpp 已公开且可逆的资源参数：

1. `R1`：`--parallel 2 --kv-unified`，替代自动选择的4 slot。产品为本机单用户串行会话，不依赖4路并发；仍保留一个前台轮和一个恢复余量，并保持4096统一KV上下文合同。
2. `R2`：`--no-host`，仅在本机构建启动、推理和回滚都正常时评估；它绕过host buffer，可能降低RAM，也可能造成不兼容。
3. 只有单变量各自通过后才允许组合；不得修改模型、提示词、TTS、UI、数据库或PRD门槛。

## 3. 实施顺序

1. 给 `RuntimeLauncher.ps1` 增加受限 `dual` slot profile 与 `LlamaNoHost` 开关，默认值保持 `auto/off`。
2. PowerShell AST解析和参数合同测试通过后，分别启动R1、R2；先做健康、单条真实浏览器链和60秒资源筛选。
3. 候选必须让Windows Available六次采样最小值≥2048MiB，且WSL Available≥2048MiB、项目RAM≤14GiB、VRAM≤22GiB、无新增swap-in，才进入10条延迟筛选。
4. 10条必须完整；P50/P95相对恢复基线不得回退超过3%。通过者再做30条确认；否则恢复默认。
5. 若全部失败，O2继续BLOCKED并停止，不以关闭用户进程、释放文件缓存或降低硬门制造通过。

## 4. 交付

- 受限且默认关闭的启动参数；
- `audit/v1/B2.5/O2R/{R1,R2,selected}` 原始指标、资源采样和失败原因；
- O2R验收报告、PRD复检和开发后审计；
- 通过则更新O2状态并进入O3，否则输出明确停线原因。
