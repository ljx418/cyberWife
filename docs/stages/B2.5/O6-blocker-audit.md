# B2.5-O6 开发前阻断审计

**日期**：2026-09-25  
**结论**：CLOSED；用户已批准推荐修订，按 ADR-009 执行

## 冲突

1. `B2.5/acceptance.md` 的OX-06要求早/中/晚各10次真实打断、P95≤400ms、旧字幕/帧/写入为0。
2. `backend-development-plan.md` 明确把`InterruptionController`、跨LLM/TTS/Avatar取消、30次打断和旧轮隔离归入B3。
3. 同一计划又规定：B2.5先回填B2 PASS，才允许进入B3。

因此形成循环：`B2.5 O6通过 → 才能进入B3`，同时`B3能力与证据 → 才能让B2.5 O6通过`。当前若继续只能提前开发B3（违反门禁）或假签OX-06（虚假验收）。

## 已批准修订

- B2.5出门只验收性能优化直接相关的OX-01/02/03/04/05/07/08/10/11/12；OX-06打断和OX-09 Avatar终止/恢复回归各自回到B3/B2（或B5总验收）。
- B2回填只签首响、TTS质量、FPS/资源和Avatar既有功能；Avatar故障恢复若尚无真实证据则作为B2独立修复，不让B3打断形成循环。
- B3完成后，在B5总验收重新运行完整OX-01～12，确保优化对打断没有回退。

此修订不降低任何用户体验门槛，只修正证据归属和阶段依赖。用户于 2026-09-25 明确批准：“B2.5验首响/缓存，B2验Avatar恢复，B3验打断，B5再做完整组合回归”。本 P1 已闭环；后续分别在能力所属阶段产生真实证据，B5 仍须完整重跑，详见 [`../../architecture/adr/ADR-009-stage-gate-ownership.md`](../../architecture/adr/ADR-009-stage-gate-ownership.md)。
