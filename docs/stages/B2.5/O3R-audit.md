# B2.5-O3R 开发前审计

**日期**：2026-09-25  
**结论**：PASS，允许按O3R计划实施

## 独立风险检查

| 编号 | 严重度 | 风险 | 闭环方式 |
|---|---|---|---|
| O3R-A-01 | P1 | `/mnt/c`大权重读取偶发不完整 | ext4副本逐文件SHA256；3次冷启动；源目录保留回滚 |
| O3R-A-02 | P1 | 放宽门槛被误用为平均值或缓存门槛 | 只认普通未命中30条P95；P50继续公开；缓存单独分桶 |
| O3R-A-03 | P1 | 为压时延引入高成本LLM运行时 | 达7秒即停止扩大复杂度；O4默认取消，不双常驻 |
| O3R-A-04 | P1 | 切换TTS造成音质或资源回退 | Qwen先验收；Cosy仅条件A/B；CER/资源/回滚同时达门才可切换 |
| O3R-A-05 | P2 | 复制模型增加磁盘占用 | 仅复制ASR约1.62GB；目标盘余量充足；不自动删除源 |
| O3R-A-06 | P1 | Cosy首响达门但Python CPU分配缓存使项目RAM越门 | 干净重启测增长；只允许收尾释放临时对象/allocator arena，之后重跑30条；禁止以关闭Avatar或降低质量换门槛 |

## 审计结论

- 规格变更有用户明确授权，已限定到NFR-01首响一项。
- 实现路径保持端口/适配器边界，是可逆配置迁移，不构成架构重写。
- 开放P0=0、开放P1=0；可进入实质开发。

## 开发后审计

- `O3-RB-01`由ext4副本、5/5哈希与3/3冷启动真实转写关闭。
- Qwen真实30条未达7秒门后才执行Cosy条件分支，未选择性跳过失败数据。
- Cosy两组各30/30完成；内存回收版P95=6.392秒，严格RSS组合约13.14GiB，体验与资源同时达门。
- TensorRT继续拒绝，O4取消；没有以高成本迁移追逐非必要时延。
- 开放P0=0、开放P1=0；授权盲听是明确的人类O6门，不属于实现缺陷。
