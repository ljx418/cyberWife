# B2.5-O2 低风险流水线优化开发计划

**日期**：2026-09-25  
**状态**：开发前计划已锁定

## 1. O1证据驱动的范围

O1 普通链 P50/P95=6.010/8.196s；P50阶段拆分为 LLM首个可播1.753s、其后到TTS首包4.176s、浏览器渲染0.218s。LLM队列最大深度仅1，因此 O2 不修改队列容量；本机 llama.cpp `--help` 证明 prompt cache 已默认开启，因此不把重复开启记为优化。

O2 只验证以下可逆单变量：

1. `L1`：llama-server `--parallel 1`，对比当前 `auto`；
2. `L2`：llama-server `--no-cont-batching`，对比当前默认连续批处理；
3. `S1`：首个可播前缀最小字符数 `10→8`，通过 `SentenceScheduler` 纯函数和 Gateway 配置注入，不改变最终文本。

不进入 CosyVoice TensorRT、vLLM、缓存、打断或模型切换。每次只改变一个变量；组合配置只允许在单变量各自通过后做确认。

## 2. 实施顺序

1. 失败测试锁定 `playable_prefix` 的标点保持、8/10阈值、上限和全文不丢失合同。
2. 把 `TurnPipeline` 的硬编码10字符改为构造参数，默认仍为10；非法值启动失败。
3. Gateway 从受限配置读取阈值；Launcher 增加受限 llama profile 参数，默认保持当前行为，禁止任意附加命令行。
4. 以 O1 同一30条、同一浏览器、同一模型和同一测量器执行A/B。单变量先10条筛选；满足收益门后再跑30条确认。
5. 只有通过30条、资源、回归和质量检查的候选才能成为新默认；否则开关回退并记录无收益。

## 3. 晋级与回退规则

- 10条筛选：候选 P50 或 P95 至少改善5%，另一指标不得回退超过3%；10/10完整。
- 30条确认：P50或P95至少改善5%，另一指标不回退；30/30完整；浏览器附加耗时不得异常扩大。
- `S1` 还必须证明拼接后全文无丢字/重复、固定TTS质量语料 CER≤5%，授权盲听不低于既有结果。
- 资源继续满足 RAM≤14GiB、VRAM≤22GiB、两侧可用≥2GiB、无持续swap-in。
- 任一候选不稳定、质量回退或资源越门，恢复默认并保留失败证据；全部无收益仍可判定 O2“验证完成、无默认变更”，进入 O3。
