# B2.5-O3R 回滚稳定化与 7 秒门槛重基线计划

**日期**：2026-09-25  
**状态**：开发前计划（用户已批准执行）

## 1. 变更依据

用户于 2026-09-25 明确允许：若继续压低首响的技术成本过高，V1 普通对话首响硬门可放宽到 **P95≤7.0 秒**。本项目据此取消 P50≤2.0 秒硬门，P50仍作为诊断指标完整报告；打断、质量、资源、隐私、稳定性门槛均不变。

该调整不是用缓存或平均值掩盖普通链路。首响仍按 `asr.final` 到浏览器首个非静音样本、预热后连续30条普通缓存未命中样本计算。

## 2. 问题与边界

- O3 TensorRT 相对同环境非TRT CosyVoice的首包P95回退约9.8%，路线维持拒绝。
- Qwen回滚首轮曾从 Windows 挂载目录读取 ASR `model.bin` 失败，重启后恢复；这是开放P1 `O3-RB-01`。
- 本批次只把主 ASR 资产复制到 WSL ext4、校验并切换注册路径；保留源目录，回滚只需恢复注册路径。
- 不改变 `AsrPort/TtsPort`、领域层、前端交互、模型内容或精度参数。
- 不进入 vLLM/TensorRT-LLM：在7秒门槛下，其迁移复杂度和内存风险已无合理收益依据。

## 3. 顺序实施

1. 记录源 ASR 目录文件清单、尺寸和 SHA256。
2. 复制到 `/home/administrator/.cyberWife/models/asr/faster-whisper-large-v3-turbo`，逐文件比对；禁止删除源目录。
3. 修改本机私有模型注册表指向 ext4；执行真实 ASR probe 和连续冷启动读取。
4. 用当前默认 Qwen + `--no-host` 跑30条真实 Edge 全链；记录分段耗时、P50/P95、30/30音频确认和资源。
5. 仅当 Qwen P95仍>7秒时，才用非TRT CosyVoice跑同语料30条公平A/B；满足质量、资源、回滚和P95门后才提出默认切换ADR。
6. 若某一路已满足P95≤7秒，停止扩大运行时复杂度，进入O5严格问候预热；预热不参与普通路径出门。

### 3.1 条件资源闭环

若CosyVoice达到首响门但组合驻留RAM表面越过14GB，先区分系统缓存与项目PSS/RSS，并执行一次干净重启后的“预热→30条”增长测量。只允许在adapter收尾处增加Linux可用、失败无害的临时张量/分配器回收；不得卸载正在服务的模型、降低精度、关闭Avatar或改变回答。优化后必须重跑30条首响与资源，任一体验回退则撤销。

## 4. 成本上限与停线

- 新增磁盘约1.62GB；不得复制Qwen、LLM或Avatar模型。
- 同一时刻只常驻一个TTS；项目RAM≤14GB、VRAM≤22GB、宿主和WSL可用内存均≥2GB。
- 发现ASR副本哈希不一致、连续冷启动仍有不完整读取、普通链30条非空不足30条、CER>5%或P95>7秒则本批次FAIL，回到计划审查。
- 达到7秒硬门后，不再以首响为由进入vLLM/TensorRT-LLM；后续只允许低风险、可回退优化。
