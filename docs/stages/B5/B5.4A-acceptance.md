# B5.4A 验收标准

## 场景一：连续真实对话

- 前置：默认主舞台、五组件functional probe为ready、Chrome麦克风已授权。
- 操作：点击一次开始，连续说3句，不点击模拟按钮；观察状态、双向字幕、声音与人物；点击结束。
- 门槛：后端创建1个真实session；每句发送的二进制帧均646字节且chunk从0递增；3/3得到`transcript.final`、`reply.text.final`、非静音播放及Avatar帧；状态转换合法；结束后WebSocket关闭、音轨全部stopped、输入AudioContext关闭、后端idle。

## 场景二：说话中插话

- 操作：角色speaking时发声，继续提出新问题。
- 门槛：浏览器发送一次匹配当前turn的`barge_in.detected`；旧generation的浏览器声源立即停止且迟到字幕/音频/帧不呈现；回到listening并正确回答新问题。量化400ms门由B5.4C组合样本签署。

## 场景三：真实故障

- 操作：拒绝麦克风权限、断开Gateway、结束后再次开始。
- 门槛：显示可理解真实错误；不得进入假listening/speaking；可重新授权/恢复后在原页再开会话；没有重复socket或重复音轨。

## 自动化与证据

- `npm run build`、输入音频单元/合同测试、后端全回归。
- Chrome E2E结果写入`audit/v1/B5/B5.4A-conversation/`，至少包含脱敏事件序列、帧计数、播放确认、资源释放快照和截图。
- 任何模拟按钮、定时器推动thinking/speaking、仅HTTP ack均直接FAIL。
