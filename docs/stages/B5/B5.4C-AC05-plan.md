# B5.4C AC-05 实时打断组合复验计划

**状态**：READY FOR EXECUTION  
**入口门**：AC-04/04A PASS；开放P0/P1=0。

## 用户场景

角色正在回答并播放声音、实时渲染嘴型时，用户在回答早段、中段或晚段重新说话。系统必须立刻静音旧回答，取消旧 generation，保持音频上下文和 Avatar 连接，并允许下一轮继续。

## 执行方案

1. 使用真实 Windows Chrome、真实 ASR/LLM/CosyVoice/Avatar 和授权长语音。
2. 早/中/晚各10次，共30次；不得删除失败行或复用历史B3结果替代。
3. 从浏览器发送 `barge_in.detected`，同时测量旧音源归零、服务端取消确认、旧generation事件、Avatar连接代次与重连次数。
4. 运行后检查 active task、模型/媒体队列与旧generation持久化增量。
5. 失败则保留完整CSV/JSON，回到打断实现或验收工具计划，不进入AC-06。

## 架构不变量

- 浏览器音频播放是主时钟；不通过延迟UI按钮伪造≤400ms。
- 取消信号只影响目标 session/turn/generation；新轮不继承旧字幕、音频或嘴型帧。
- 打断不关闭 AudioContext、不重连 Avatar、不重启模型。
- 本门不放宽B3已签署的400ms硬门，也不增加硬件占用。
