# B5.6 V1冻结与最终出门计划

**状态：READY FOR IMPLEMENTATION**  
**入口：** B5.5正式AC-14、数据生命周期、回归与PRD检视PASS；开放P0/P1=0。

## 目标

把已通过的同一候选固化成可复核、可一键打开、边界明确的V1发布候选，不新增产品规格，不重做G-UX视觉。

## 实施顺序

1. **F1 一键交付闭环**：Gateway在API/WS路由之后托管`prototype/dist`；缺少构建产物时明确503而非假页面。增加Windows双击启动/停止入口，启动成功后打开`http://127.0.0.1:7860/`；验收路径可禁止自动开浏览器。
2. **F2 浏览器发布回归**：将旧Vitest占位a11y规格替换为真实Playwright+axe、焦点圈闭与reduced-motion断言；执行生产构建和完整`npm run test:e2e`。
3. **F3 模型与工作流冻结**：7个ACTIVE logical_id必须与ComfyUI保留索引完全一致、状态verified、许可证approved、主工件有SHA256或明确的integrity_id；Silero JIT固定实测SHA256。`faster-whisper-large-v3`继续只列删除候选，不自动删除。
4. **F4 发布清单**：生成源码/依赖文件SHA256、生产前端构建工件SHA256、运行时版本、关键证据摘要、模型去路径摘要和工作流覆盖摘要。源码集合排除私有配置、用户资产、模型权重、audit正文、node_modules、dist和缓存；`prototype/dist`仅作为独立发布工件集合记录；清单不得泄露绝对私有路径。
5. **F5 独立审计**：复跑后端/Avatar/前端、静态托管与一键入口合同；逐条核验FR-01～20、NFR-01～10、AC-01～14、AC-04A与OX-01～12，形成V1 Go/No-Go结论。

## 不做

- 不删除任何模型或用户数据；不修改G-UX视觉；不引入Docker、联网天气或云服务。
- 不重跑已通过且候选未受影响的60分钟模型soak；若一键静态托管或启动器修改影响进程/资源合同，则退回B5.5重新验收。

## 出门

一键双击后同一受管Gateway可打开真实生产前端；完整Playwright通过；冻结清单可重复生成且无私密路径；7模型/7工作流一致；关键B5证据全部PASS；开放P0/P1=0，方可签署V1 Go（个人/研究用途，Wav2Lip商业限制明确）。
