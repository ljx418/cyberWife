# B5.4C AC-06 Avatar实时嘴型与恢复组合复验计划

**状态**：READY FOR EXECUTION（路线1+2于2026-10-04获批）  
**入口门**：AC-05 PASS；真实四进程健康；开放P0/P1=0。

## 用户场景

正常回答时数字人嘴型随语音实时渲染。Avatar进程意外退出后，页面在2秒内切换静态形象，但声音和完整文字继续；单项恢复后不刷新页面，下一轮重新以至少25 FPS渲染嘴型。

## 执行步骤

1. Windows Chrome在同一页面打开真实MediaSession和AvatarSession。
2. 每周期先开始真实回答，在已有音频和嘴型帧后精确终止受管Avatar PID。
3. 验证静态降级≤2秒、故障后仍有音频块、文字final完整。
4. 调用受管恢复入口，只恢复故障组件；等待同页连接代次增加且状态ready。
5. 发起下一真实轮，采集浏览器final FPS、decoder backlog和Avatar inferfps。
6. 共3周期；页面reload必须为0。运行后补采健康、资源和队列快照。

## 实施实体与顺序

1. `workers/avatar/control_server.py`：同进程独立线程、loopback 8011、最小`/healthz`。
2. `workers/avatar/server/routes.py`：帧间隙500ms发送`avatar.heartbeat`，不创建第二个写协程。
3. `prototype/src/services/AvatarSession.ts`：1200ms媒体watchdog、500ms控制探针、软/硬降级分流、真实解码帧恢复。
4. `ops/windows/RuntimeLauncher.ps1`：启动参数显式传入8011，Avatar启动门同时校验8010与8011。
5. 先执行单元/构建/白盒合同，再执行1周期诊断，最后执行3周期真实验收。

## 停线条件

- 任一周期未降级、超过2秒、音频被Avatar故障阻塞或文字丢失；
- 恢复依赖页面刷新，或下一轮无嘴型、final/inferfps<25、backlog>3；
- 恢复误重启健康的LLM/Speech/Gateway，或资源越过RAM/VRAM硬门。
- 健康推理期间出现软降级、硬重连或session争抢；8011暴露非loopback或响应含用户数据。
