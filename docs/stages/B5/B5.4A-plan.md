# B5.4A 批准主页面真实对话接线计划

**状态**：READY FOR IMPLEMENTATION  
**基线**：G-UX 已批准，禁止视觉重构；B5.1～B5.3 PASS。

## 目标与边界

把默认 `App.tsx` 主舞台从原型模拟接到既有本地 Gateway，不改变批准的布局、视觉语言和路由。浏览器取得麦克风授权后创建真实 session，通过单条 WebSocket 连续发送 16 kHz/20 ms/mono/PCM16 帧，并消费后端六态、双向字幕、音频和 Avatar；结束会话必须释放音轨、AudioContext、WebSocket和后端 session。

本子阶段不重做五步设置、不修改模型方案、不改变7秒普通首响门；这些分别由B5.4B和B5.4C签署。

## 实现实体

1. `prototype/src/services/InputAudioSession.ts`：浏览器麦克风、48k/任意输入重采样到16k、20ms切帧、前置缓冲、语音起止、静音封口、轨道释放。
2. `ConversationClient`：创建/结束/切换不记录session，并保持6字段事件信封和646字节音频帧合同。
3. `App.tsx`：真实开始/结束、事件驱动六态、用户/角色字幕、说话中插话、错误与恢复文案；移除默认页面模拟入口。
4. 既有 `MediaSession`/`AvatarSession`：继续负责真实播放确认、代次取消和H.264呈现，不复制媒体状态。

## 实施顺序

1. 先写纯函数与浏览器合同测试：重采样、640字节切帧、严格递增chunk、一次封口、资源释放。
2. 接通session REST和WS，状态只由后端事件推进；本地只允许麦克风权限/连接错误进入error。
3. 插话时先发送`barge_in.detected`并立即停止旧代次播放，再开始新turn；迟到事件由turn/generation/seq共同丢弃。
4. Chrome使用真实授权音频或虚拟麦克风完成至少3轮；保存事件序列、字幕、可听播放/Avatar帧和结束清理证据。
5. 复跑后端回归、前端构建和B5.3白盒，完成PRD检视后才能进入B5.4B。

## 回退策略

前端接线失败只回退本子阶段文件，不改Gateway协议。Avatar不可用时保留文本/语音并展示静态人物；ASR/LLM不可用时禁止假对话并给出真实恢复动作。
