# B5.4C 发布候选组合开发计划

## 目标

在不改变已批准 G-UX 的前提下，把 B0～B5.4B 已通过能力组合到同一发布候选并关闭“单项通过、组合失效”的风险。B5.4C 不替代 B5.5 的一小时生命周期演练，也不提前宣告 V1 Go。

## 开发前规格映射

| 工作包 | PRD/AC | 实体 | 本阶段出门证据 |
|---|---|---|---|
| C1 真实状态与错误合同 | FR-03/07/15，AC-11/12 | `App`、`ApiGateway._http_exc_handler` | 未加载不显示ready；18类错误码不被前缀文本降级成internal.error |
| C2 键盘/读屏/响应式 | FR-16，NFR-08，AC-11 | `SettingsDrawer`、主舞台、CSS | 三尺寸；焦点圈闭与恢复；命名、live region、reduced-motion |
| C3 降级合同 | FR-10/15，AC-06/12 | `RuntimeLauncher`、TTS/Avatar adapter、health | Cosy启动失败可单向回退Qwen；运行中TTS失败保留文字；Avatar失败保留语音和静态图 |
| C4 同候选组合回归 | AC-01～13、AC-04A | `tests/b5`及既有B2.5/B3/B4 runner | 真实Chrome、真实模型、真实SQLite/文件、原始样本与资源曲线 |

## 实施顺序

1. 先修正错误码解析、健康状态呈现与设置抽屉焦点圈闭；所有改动先有自动断言。
2. 检视并补齐TTS单向回退；禁止Cosy与Qwen双常驻，禁止自动抖动切回。
3. 执行静态合同、后端全量、前端构建和三尺寸Chrome验收。
4. 执行同一候选的对话、首响/缓存、打断、Avatar、记忆/隐私、恢复组合；失败返回对应阶段，不修改门槛。

## 资源与安全约束

- 本机预算：RTX 4090；项目RAM硬门14GiB，宿主/WSL各保留2GiB；VRAM≤22GiB。
- 任何时候只驻留一个TTS；fallback是单向且要显式显示。
- 不执行会中断宿主终端的物理断网；AC-13按用户批准改为功能完备性、白盒无联网上传和真实进程出站检查。
- 不删除正式用户资料；验收使用隔离SQLite/资产根。

## 停线条件

- 同候选出现P0/P1：旧轮串流、删除后召回、外网上传、首响P95>7s、打断P95>400ms、Avatar<25fps、资源越门。
- 降级只能依靠双TTS常驻，或需要突破当前内存预算。
- 自动证据无法区分真实模型结果与fixture/mock。
