# B5.4C AC-04A 缓存组合复验计划

**状态**：READY FOR EXECUTION  
**候选约束**：与 `B5.4C-AC04-normal30` 使用同一运行候选、真实 Windows Chrome、真实 ASR 与浏览器播放确认。

## 目标与边界

- 复验严格问候缓存不会把动态问题、记忆请求或附加语义错误命中。
- 正例必须经过真实音频、ASR、WebSocket、Avatar 推送和浏览器非静音确认；不得直接调用缓存对象冒充端到端命中。
- 版本失效、24 条语义负例、64 MiB 内存上限使用产品实际领域类验证。
- 缓存保持进程内；不增加 SQLite 表、缓存文件、后台模型或公网依赖。
- 本门不改变已批准的白名单、回答内容、UI 或 7 秒普通首响门槛。

## 实施与验收顺序

1. 补齐命令清单已引用但缺失的 `tests.b25.accept_warm_cache` 单一验收入口。
2. 对运行目录和 SQLite schema 做验收前快照。
3. 使用能被真实 ASR 转写为“你好”的授权测试 WAV 连续运行 3 轮 Chrome 链。
4. 对 24 条明确负例、五个版本维度、内存拒绝行为运行产品类断言。
5. 对比运行目录和 SQLite schema，生成不含正文的 JSON 汇总。
6. 任一断言失败保留证据并停止进入 AC-05。

## 停线条件

- 正例不是 3/3 `cache-hit`、P95 超过 800 ms、未发生浏览器非静音确认；
- 24 条负例任一命中，或版本变化后仍命中；
- 缓存对象超过 64 MiB，出现缓存专用 SQLite schema/文件；
- 普通链证据不是 30/30、P95 超过 7 秒或混入 `cache-hit`。
