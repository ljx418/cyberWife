# ACC1 详细开发与验收计划：AC-11与物理输入补证

**日期**：2026-10-05

## 目标

在1920×1080、1366×768、420×720三个视口，以键盘完成设置、开聊、打断、改人设、删记忆；验证六态播报、焦点恢复、对比度、减少动效。另以Windows Chrome默认物理麦克风完成自由对话，确认真实权限、采集、ASR与连续多轮。

## 实施顺序

1. 把五项核心任务写成复用的Playwright旅程，逐视口执行并保存步骤/断言结果。
2. 旅程使用生产React构建和真实Gateway合同；为避免删除用户数据，测试后端使用隔离临时SQLite与明确的测试记录，不接触正式`~/.cyberWife`。
3. 提取Accessibility Tree/aria-live状态并做axe、键盘焦点、reduced-motion联合检查。
4. 只读检查Windows NVDA/Chrome/录音设备可用性。
5. 需要真实桌面焦点前提前通知；由Chrome访问正式Gateway，用户只负责说话/判断读屏，人类输入不承担审计工作。
6. 自动核对会话事件、ASR final、回复音频、打断generation与日志无原始音频落盘。

## 非目标

- 不用授权WAV冒充物理麦克风，不用Accessibility Tree冒充真实NVDA播报。
- 不修改已批准视觉方向，不读取或删除用户正式记忆。
