# V2-X3.4-R1 末段口型异常审计

## 结论

**确认存在产品缺陷与验收工具漏检，撤销本阶段自动全绿结论。** 该问题同时出现在原候选与中位脸框候选，因此不是坐标稳定化引入的回归。

## 可复现证据

- 输入 WAV 长度为 8.000 秒，但可识别人声约在 6.7～6.9 秒结束，7.5～8.0 秒为全零 PCM。
- 三段原候选视频时长分别为 8.800、8.840、8.880 秒；三段稳定候选时长相同。
- `BaseASR.put_audio_frame()` 将每个外部 PCM 包固定标记为 `type=0`，尾部静音仍被识别为“说话”。
- `BaseAvatar.inference()` 以整批是否存在 `type=0` 判断说话，因而在尾部静音批次继续执行 MuseTalk 口型推理。
- 雨夜书房在 6.9～8.0 秒静音段的嘴部一阶运动均值为 1.356，高于 0～6.7 秒人声段的 1.146；二阶运动为 1.836，高于人声段的 1.502，符合人工观察到的静音抖动。

## 验收漏检

1. `capture_lipsync.py` 默认额外采集 1.2 秒，并在封装时为音频补静音。
2. H.264 输出将最后一个 generation 沿用到 Idle 帧，使收尾 Idle 也被当前 generation 的采集器收录。
3. `analyze_lipsync.py` 使用 `min(video_frames, audio_energy_frames)` 截断相关性计算，8 秒之后的异常帧不进入 A/V 响应门。
4. 现有门只比较整段“人声/静音均值”，没有“最后有效语音之后必须闭嘴并稳定”的独立尾段门，导致整体 PASS 掩盖局部失败。

## 建议修复边界

1. 为 Avatar PCM 增加可审计的语音/静音状态或低延迟尾静音判定，不再将所有外部 PCM 固定标为说话。
2. 按每个 40ms 视频帧对应的两个音频帧选择推理结果或 Idle，避免一个有声帧让整批尾部静音都继续口型推理。
3. 增加 generation 结束信号，完成右上下文排空后明确切回 Idle；不得靠超时猜测回答结束。
4. 修正采集器：口型 A/B 主证据严格按输入时长封装；收尾过渡另做独立证据。
5. 修正分析器：新增“最后有效语音后嘴部运动衰减”“尾部无抖动”“音视频有效区间一致”硬门，并用三场景真实 PCM 重验。

在上述缺陷闭环前，R1-AC02、R1-AC03 与 R1-AC06 不得签署。
