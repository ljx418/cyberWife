# V1RC1-R3 修复计划：CosyVoice2 流式首包窗口复位

**触发证据**：R2 Chrome 真实30轮功能30/30、P50=5989.209ms，但P95=7727.328ms，仍未达到7秒门槛；WSL `MemAvailable` 约7.2GiB、Swap=0，排除内存压力。

## 白盒根因

本机冻结的 CosyVoice2 `CosyVoice2Model.tts()` 直接修改实例字段 `self.token_hop_len`：首个窗口从25逐步放大到100，推理结束不复位，后续请求首包因此从100 token才开始解码。相邻的 CosyVoice旧实现使用局部 `token_hop_len`，且注释明确“逐步增加”，不支持跨请求永久继承。

## 最小修正

- 模型加载完成时记录冻结版本声明的初始 hop 窗口。
- 单工作线程每次调用 `inference_zero_shot` 前恢复初始窗口。
- 单次推理内部仍由上游从25→50→100递增，保留其后续音质/吞吐折中。
- 不修改依赖仓文件，避免安装重建覆盖；兼容补丁封装在项目适配器内。

## 验收标准

- 合同测试证明连续请求前均恢复初始窗口，缺字段的未来实现安全跳过。
- 定向与全量自动化通过。
- Windows Chrome真实30轮功能成功率≥95%、首响P95≤7000ms、active Crop V2、视频协议v2。
- 音频仍为单次整句合成；不恢复碎片TTS，不改变音色、采样率与播放协议。
