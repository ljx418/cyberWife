# UX9 对话可懂度与抗误打断开发计划

**日期**：2026-10-06
**目标**：修复播放态环境噪声易触发打断的问题，并建立“合成用户语音→真实ASR→真实LLM→真实CosyVoice→输出音频再识读”的可重复验收门。

## 范围

1. 为浏览器输入边界增加状态感知：普通监听与播放态插话使用不同的RMS及持续时间门槛。
2. 保留900ms自然停顿，不修改后端打断后的generation清理、400ms静音门和用户主动按钮打断。
3. 新增本机真实模型闭环执行器；输入和输出音频均为16kHz、单声道、PCM16并在内存中处理。
4. 对输入ASR、回复文本、输出音频ASR分别评分，避免“有声音/有文字”冒充“可交流”。
5. 以确定性场景覆盖问候、事实问答、情绪回应、建议、上下文记忆和追问，不使用外部网络或云模型。

## 实施顺序

1. 冻结UX9验收标准和开发前审计。
2. 先增加打断边界单元/浏览器合同测试，再修改`InputAudioSession`。
3. 实现脱敏闭环执行器和语义评分器，先跑当前基线并记录真实失败。
4. 根据失败归因，仅调整提示词、采样参数、响应规整或TTS调度中确有证据的问题。
5. 重跑真实闭环、既有Backend/根/Avatar/Playwright回归及PRD规格检视。

## 停线条件

- 输出音频无法被真实ASR识读，或音频识读结果与`reply.text.final`明显不一致；
- 语义门必须依赖主观猜测或云端裁判才能通过；
- 抗误打断改动使真实插话确认超过400ms；
- 需要突破现有16GB空闲内存、22GB VRAM或离线边界；
- 修复需要更改已冻结的generation/取消协议。
