# V2-X3 开发前审计

**结论**：BLOCKED；原 `X3-P1-01` 的顺序修正已获批准，但真实数据复核新增 `X3-P1-02`，未进入实质实现。

- 复用X0 manifest与CAS，不新增数据库或双写active指针。
- 背景是项目内公开静态资产，可进入PWA白名单；外观源图仍通过私有source API且不缓存。
- 前端采用“后端提交成功后再切画面”，CAS或网络失败不会出现一半切换状态。
- 会话/turn不进入预设事务，切换不会重建WebSocket、麦克风、AudioContext或AvatarSession。
- 同一完整场景Idle只有匹配scene_id时使用；缺失回退背景+当前人物，拒绝拼接第二人物。
- 外观标签来自X1用户确认，不做视觉推断；不同标签分组必须引用当前pack源图。
- 该阶段不启动生成模型，内存/显存冲击可忽略。

## 阻断项 X3-P1-01：外观预设没有可播放rendition

X1当前只交付源图、角度与用户穿着标签；现有活动Idle/说话Avatar只对应一套已批准外观。若X3仅切换`active_appearance_id`，用户看见的衣着不会变化；若直接把另一张source图铺到舞台，进入Idle/说话后又会跳回旧外观，并可能造成静态/动态双人物。这两种做法都会虚假满足X3-AC03，并违反单人物、同场景、无闪动和体验无回退硬门。

推荐阶段门修正：

1. **X3A 场景预设**：先实现4个背景的稳定UUID、真实SHA、CAS切换、失败回退和重启恢复；不开放无rendition的外观按钮。
2. **X4 外观rendition准备**：在低幅Idle阶段为至少2个用户确认外观生成并人工批准同场景Idle/说话兼容素材。
3. **X3B 外观激活**：只有appearance绑定已批准Idle与talking rendition后，才开放原子外观切换并执行3场景×2外观组合验收。

该调整改变已批准的X3→X4严格顺序，需要项目所有者确认。确认前不得用元数据切换冒充视觉外观切换。

## 阻断项 X3-P1-02：其余场景没有说话态完整场景rendition

运行数据仅有一个已批准完整场景 `speaking_avatar_id`。其余三个内置背景只有静态WebP，没有对应的低幅Idle与说话Avatar数据集。直接开放切换会在开口时跳回旧背景，属于X3-AC03禁止的虚假验收。

推荐把已批准顺序进一步细化为 `X3A0目录/CAS → X4S缺失场景素材生成与人工批准 → X3A1动态场景激活 → X4A两套外观rendition → X3B组合激活`。详细证据与路线比较见 `scene-speaking-surface-audit.md`；该细化需项目所有者确认。
