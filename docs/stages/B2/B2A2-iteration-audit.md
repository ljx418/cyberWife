# B2-A2 首轮组合验收打回与修订审计

**日期**：2026-09-25  
**结论**：首轮3周期 FAIL并保留；修订后三周期 PASS，P1已闭环并签署B2

## 1. 失败事实

首个单周期冒烟通过；随后3周期真实组合回归的模型、音频连续性、NVENC、服务端FPS和原页恢复均工作，但未满足严格出门门：

- Gateway `media.state=static_fallback` 相对外部终止请求为 3.285s、3.462s、2.171s，超过2秒。
- Chrome短窗口帧数除以墙钟得到 24.888/24.993 FPS，存在边界量化；服务端同期为25.026/25.108 FPS。

因此该轮机器结果保留为失败证据，不作通过解释。

## 2. 根因与修订

| 编号 | 根因 | 修订 | 验证要求 |
|---|---|---|---|
| P1-A2-01 | Avatar PCM POST 使用2秒超时；故障时单个可选口型请求阻塞后才发静态降级 | 仅 `push_audio` loopback 超时收紧至350ms；浏览器PCM仍独立继续 | 三周期 `fallback_ms≤2000`，音频chunk无减少 |
| P1-A2-02 | 编码时钟在ASR/线程预热前启动，首批帧追赶；2秒墙钟采样又有单帧量化 | 第一帧才启动25FPS时钟；客户端维护最近128帧呈现时间并报告真实FPS | 三周期客户端/服务端均≥25，无突发积压 |
| P1-A2-03 | Windows launcher 后台子进程继承句柄使同步审计调用等待 | E2E恢复命令改为独立异步启动，验收由健康和连接代次判定完成 | 恢复调用不阻塞，仍校验所有权PID和代次 |

## 3. 规格与风险复审

- 未降低2秒、25FPS、三周期、真实模型或资源门槛。
- 350ms超时只作用于可丢弃的Avatar口型副本；Gateway PCM音频主路径不受影响。
- 第一帧启动编码时钟消除预热追帧，不改变25FPS语义。
- 开放新增 P0/P1=0；重跑若仍失败，再次返回计划阶段。

## 4. 修订后独立复验

- 三轮用户可见降级：522/540/537ms；均≤2秒。
- 三轮媒体节奏25fps、decoder backlog=0、WebSocket队列丢帧=0、服务端finalfps≥25。
- 三轮Avatar终止后仍有非静音PCM，恢复后下一轮文本和音频均完成，页面reload=0。
- 资源与全量回归PASS；详见`B2A2-result.md`。首轮失败证据未覆盖、未删除。
