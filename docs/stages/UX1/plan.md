# UX1 人物资产与画面状态开发计划

## 目标

关闭五项已复现体验缺陷中的确定性根因：上传写真未进入 Avatar 数据集、浏览器固定裁切导致脸部不可见、停止后不透明 Canvas 变黑。动态底片、嘴型 A/B 与 TTS 自然度在本门通过后串行实施。

## 实施顺序

1. 为写真派生物增加可审计的数据状态和源 SHA 绑定。
2. 上传写真后构建内容寻址的 Wav2Lip Avatar，并在派生物 ready 后原子激活写真与 Avatar。
3. H.264 WebSocket 按激活的 `avatar_id` 建立会话，不再固定默认人物。
4. 浏览器使用显式静态/连接/实时/降级/停止图层状态；停止时恢复写真而不是显示被清空的不透明 Canvas。
5. 静态与动态层共享人脸安全焦点，在五种目标视口验证。

## 风险闭环

- 构建失败：旧人物保持 active，新写真停留 previewed，禁止半激活。
- 路径注入：Avatar ID 仅允许内容寻址的字母数字、下划线和连字符。
- 内存增长：Avatar worker 只缓存默认人物、当前人物和一个回滚人物。
- 隐私：API 不返回写真绝对路径；审计只记录 SHA/ID 派生标识。
