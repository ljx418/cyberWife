# V2-X-D1 验收标准

## D1-AC01 需求与实体追踪

操作：从PRD的V2-R01～R14和V2X-AC01～15逐项查到实现合同。  
硬门：每项都有责任实体、输入输出、失败/回退、真实证据；缺项为P1。

## D1-AC02 架构完整性

操作：检查目标架构和Draw.io。  
硬门：依赖保持`api/UI → application/services → domain + ports ← adapters/infrastructure`；图中所有运行实体均能对应现有或计划文件；≤8页、中文、状态色一致。

## D1-AC03 数据与迁移

操作：对source-pack/appearance/scene/rendition manifest、用户确认视觉描述和记忆派生图执行创建、重复执行、失败注入和回滚推演。  
硬门：稳定UUID不重写；原图只读；临时文件不能被读取为active；失败保持V1活动资产；删除源记忆后派生节点/边零残留。

## D1-AC04 实时状态与回退

操作：对输入校准、PTT、页面隐藏、断网、服务恢复、音量/重播、微动作、质量降级逐事件推演。  
硬门：generation fence仍是音视频失效权威；活动麦克风轨道≤1；旧轮不复活；音频优先；每项feature flag可独立退回V1。

## D1-AC05 资源、隐私与验收真实性

操作：检查缓存白名单、日志字段、模型驻留计划及验收数据来源。  
硬门：私有图片/音频/记忆/鉴权不进入Git和Service Worker；重型生成与实时模型不双驻；机器测试不代签主观自然度/身份保持。

## D1-AC06 双轮审计

操作：内部审计后以不同清单执行外部审查。  
硬门：开放Critical/P0/P1=0；P2有责任人、触发器与回退；文档互链有效且没有相互冲突的状态。

## 出门

D1-AC01～06全部PASS后，X0可进入“先写计划/验收/开发前审计，再编码”的自动化开发流程。D1 PASS不签署任何V2X功能验收。
