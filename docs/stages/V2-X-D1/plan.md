# V2-X-D1 架构与开发文档计划

**日期**：2026-10-08  
**阶段性质**：文档开发与审查；不修改产品运行代码  
**入口**：G-V2X-D0 PASS

## 目标

把已批准的V2-X交互原型转换为可顺序自动开发的实现合同，并保持V1单人物实时链、离线边界和资源门不回退。

## 工作顺序

1. 以当前代码、PRD、D0原型和ADR-013为事实源，建立As-Is实体清单。
2. 给X0～X9逐项指定新增/修改/复用的代码实体、依赖方向、状态机、事件和存储合同。
3. 比较至少两种实现路线，记录选择、代价、迁移和逐项回退。
4. 制作不超过8页的中文Draw.io，覆盖目标差异、实体交互、里程碑、验收和停线条件。
5. 执行需求覆盖、架构一致性、可验证性、隐私资源和语义冲突五类内部审计。
6. 用独立的外部审查清单复核可执行性与虚假验收风险；P0/P1为0才开放X0。

## 明确不做

- 不在D1修改React、Python、SQL、启动脚本或模型工作流。
- 不提前实现V2-A多角色、多空间、导入导出或外部插件宿主。
- 不把D0交互原型或架构图当作功能验收证据。

## 停线条件

- 目标代码实体无法在当前依赖方向实现；
- 需要实时与生成模型双常驻或突破14GB项目RAM/22GB VRAM；
- 未确认视觉推断可直接进入长期记忆；
- Service Worker缓存私有正文/媒体；
- V2-X出现多角色/多空间管理或插件写核心记忆；
- 任一验收项没有真实操作、失败判据或证据来源。
