# V2-X8.0 开发计划：实时口型模型链校准

## 用户结果

在不替换已批准`scenev2_mouth`活动基线、不突破单机约16GB空闲内存和RTX 4090 24GB边界的前提下，确认下一阶段应继续优化Wav2Lip256，还是把MuseTalk 1.5作为V2-X8主候选。结论必须来自同人物、同场景、同音频、同25fps传输链的真实A/B，而不是项目演示视频或FPS单指标。

## 当前事实链

```text
16kHz PCM
  → MelASR（40ms特征）
  → Wav2Lip256（256×256人脸框；输入含原脸+下半脸遮蔽副本）
  → manifest融合profile（当前mouth_oval_v1）
  → 768×432完整场景帧
  → NVENC H.264 / WebSocket
  → Chrome WebCodecs；浏览器音频时钟为唯一主时钟
```

当前不是把人物从背景抠出后再叠加。Wav2Lip接收完整的256×256人脸裁剪并预测整张脸，`mouth_oval_v1`仅决定预测结果贴回原完整场景帧的范围。`full`模式已经存在，可用于整脸回贴对照；它也不会让Wav2Lip处理整幅768×432场景。

## 候选路线

| 路线 | 任务链 | 预期收益 | 架构冲击 | 本阶段处置 |
|---|---|---|---|---|
| A Wav2Lip256口周融合 | 维持当前链；改进时序/自适应口周mask | 成本最低、吞吐最高、可立即回退 | 小 | 活动基线 |
| B Wav2Lip256整脸回贴 | 同模型，预测脸框整体覆盖源脸 | 消除口周mask内部接缝的可能性 | 小 | 已做同输入A/B；指标劣化，不激活 |
| C MuseTalk 1.5 | PCM→Whisper tiny特征→预计算VAE latent→单步UNet→jaw face parsing→原完整帧 | 更好的清晰度、身份一致性与唇音准确度候选 | 中；数据集、模型装载、启动器和模型注册需扩展，浏览器协议可复用 | 推荐串行canary |
| D LatentSync 1.6 | PCM/视频→512 latent diffusion→离线视频 | 512脸部细节和更强时序候选 | 大；非实时任务链 | 仅离线导出研究，不进入实时主链 |
| E Duix/HeyGem类 | 个体视频训练/专有avatar资产→其运行时 | 演示保真与动作较强 | 大；公开桌面版是离线合成，移动实时SDK的自定义形象需供应商流程 | 不作为V2-X8可替换引擎 |

## 实施顺序

1. 冻结当前`scenev2_mouth`活动ID、输入WAV SHA、浏览器/Avatar协议和资源基线。
2. 同模型A/B `mouth_oval_v1`与`full`；新增上半脸身份改写、脸颊边界净扰动、锐度、二阶运动诊断。
3. 核对本机MuseTalk 1.5代码、权重、依赖、许可证、磁盘与资源；只下载经SHA登记的最小权重集合。
4. 以独立模型ID预处理当前蓝调客厅250帧；先离线/直连canary，后接相同H.264传输；不覆盖活动绑定。
5. 使用相同8秒真实CosyVoice输入采集Wav2Lip/MuseTalk视频、时间线、资源和质量数据，生成盲评页。
6. 机器门全绿后由项目所有者评清晰度、同步、嘴部自然度、身份保持；未获批准则保持Wav2Lip活动基线。
7. 只有canary通过后，才设计可回退的`avatar.engine`选择与X8正式迁移；不让两种Avatar模型常驻。

## 回滚与边界

- 全程使用独立候选ID和私有模型目录；活动场景绑定不指向候选。
- 任一候选finalfps<25、GPU/RAM越界、黑帧/双人物/冻结、身份保持或自然度低于基线，立即回退当前Wav2Lip路径。
- 不以超分插值冒充模型有效清晰度，不以Lip-Sync模型演示替代本项目当前人物证据。
- X8.0只做路线校准；X3.4其他外观和X3.5组合预设仍按原顺序验收，不被单人物结果代签。
