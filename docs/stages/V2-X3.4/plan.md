# V2-X3.4 开发计划：外观动态素材

## 用户结果

在不更换人物身份、不增加浏览器人物图层的前提下，为当前已批准人物补齐第二套“蓝白碎花上衣”外观，并为至少三个场景生成同一完整画面的 Idle 与 MuseTalk 口播派生资产。

## 实现顺序

1. 从当前已批准人物源图生成第二外观的完整场景关键帧；身份源图是唯一人物依据，其他测试人物不得混入。
2. 使用本机 Qwen Image 2.1 双参考生成三个 16:9 完整场景关键帧，提示词固定同一身份、蓝白碎花上衣、正脸半身、闭嘴、单人物和场景光影一致。
3. 使用本机 Wan 2.2 串行生成 10 秒低幅 Idle；不得抠图、透明合成或把人物铺到背景上。
4. 以每段完整场景 Idle 构建 MuseTalk 1.5 数据集；Idle 和说话态必须来自同一视频帧面。
5. 保存版本化 appearance manifest、来源 SHA、提示词、seed、质量结果和回滚点；人工批准前不激活。
6. 完成机器门后生成本地 HTML 对比页，集中进行身份、服装、光影和自然度人工批准。

## 资源纪律

- 离线 Qwen/Wan 与实时 LLM/Speech/Avatar 不双常驻；生成脚本负责停旧、执行、finally 恢复。
- WSL 内存不超过 16 GiB 配额，RTX 4090 显存不超过 24 GiB；记录峰值，超限即失败。
- 所有输入输出留在本机私有目录和 `127.0.0.1` ComfyUI。

## 明确不做

- 不把 `图片-1/2/3` 中的其他人物当作当前人物外观。
- 不用静态换图、遮罩、抠图或双人物页面冒充动态外观。
- 不以人脸检测、相似度或自动评分代替用户对身份和自然度的批准。

## 回滚

候选只写入独立外观目录；未批准、生成中断或质量门失败时，当前红色外观、活动场景、对话状态和 `scene-bindings.v1.json` 均保持不变。
