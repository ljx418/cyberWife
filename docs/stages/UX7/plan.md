# UX7 开发计划：普通话识别与连贯口播

**日期**：2026-10-05  
**状态**：开发中

## 用户问题与证据

- 用户真实交互中，普通话被显示为繁体/粤语风格，例如“沒想到”“我還會”“已經”。
- `FasterWhisperAdapter` 虽锁定 `language="zh"`，但没有普通话简体提示，且默认会沿用前文解码上下文。
- 网关日志显示一条回复会被拆成多个 4～17 字的独立 CosyVoice 推理，并持续出现“目标文本短于参考文本，可能导致效果变差”警告；每次推理都会重新建立韵律。

## 实施范围

1. ASR 固定 `task=transcribe`，增加普通话简体上下文提示，关闭跨片段前文条件，保持本地 large-v3-turbo 与现有进程边界不变。
2. 保持已验证的 beam=1；识别结果在进程内经 OpenCC `t2s` 做确定性字形归一，普通话提示不承担 100% 简繁转换职责。
3. CosyVoice 对每条最终回复只发起一次推理；取消 LLM 尚未完成时的短前缀抢跑和句间重复起声。
4. 保留文本增量显示、20ms PCM 帧、Avatar 音频时钟、打断取消、缓存命中与失败降级合同。
5. 不引入云端服务、不更换模型、不修改 Crop V2/Idle 和前端布局。

## 预期体验与代价

- 听写更稳定地显示为普通话简体中文；专有名词准确率仍受麦克风、环境噪声和 Whisper 模型能力约束。
- 两句以内的短回复保持同一音色、语速和情绪，不再在标点处重置韵律。
- 代价是等待完整 LLM 回复后才启动 TTS，预计首响增加约 1～3 秒；硬门仍为用户已批准的 7 秒内。

## 回退条件

- 真实首响任一有效样本超过 7 秒，不得恢复碎片化 TTS 冒充达标；应回到整句长度和模型运行态诊断。
- 打断超过 400ms、音频/Avatar 时钟不单调或出现文本丢失，整项回退并保持 UX7 未通过。
- 自动测试不能替代用户对口播连贯性的听感复验。
