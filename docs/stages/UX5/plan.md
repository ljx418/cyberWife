# UX5 详细开发计划：真实口型同步量化与体验闭环

**日期**：2026-10-05

**前置门**：UX4 PASS；用户批准继续后续开发

**目标体验**：使用用户已批准的 10 秒动态待机素材，在角色发声时由同一份 16 kHz 单声道 PCM 驱动声音与 Wav2Lip；说话段嘴部持续响应语音，停声后回到动态待机，不黑屏、不冻结、不以 FPS 冒充口型正确。

## 范围与非目标

- 本阶段只补齐 PRD FR-10“人物画面与音频同步”的量化证据与必要修复。
- 不改变 G-UX 已冻结的前端布局，不引入公网运行依赖，不改变 Gateway 音频主时钟。
- 不把 Idle 视频的首尾平滑度当作口型同步证据。
- 不把公共 SyncNet 与 Wav2Lip 论文中不可比的绝对 LSE 分数写成 V1 硬门；公共模型仅作诊断，并用人为错位对照校准。
- Wav2Lip 仍受 ResearchOnly 限制；本阶段不解除商业发布 NO-GO。

## 实施顺序

1. 新增 `tests/ux5/capture_lipsync.py`：校验输入 WAV，打开真实 H.264 WebSocket 会话，按 20ms 节奏向同一 session 注入 PCM，按 generation 收集实际 Wav2Lip 帧并保存时间戳。
2. 将 Annex-B H.264 与原始 WAV 封装为私有验收 MP4；证据清单只记录散列、采样率、帧数、时钟与指标，不记录正文或用户素材。
3. 新增 `tests/ux5/analyze_lipsync.py`：以人脸坐标下半区的运动能量与音频短时能量做相对时移分析，并生成 `0/±200/±400ms` 控制样本比较。
4. 若本机能隔离运行公共 SyncNet，则补充诊断分数；若不能，必须明确记为 `NOT_RUN`，不得影响传输时钟门，也不得伪报感知质量通过。
5. 若真实样本未达门槛，依次检查时间基准、音频缓冲、generation 栅栏、脸部裁切和融合参数；修复后重跑全部控制样本。
6. 输出真实视频、JSON、CSV 和阶段验收报告；人工只审看最终视频的自然度，不替代自动化时钟与对照测试。

## 资源与隐私约束

- 复用已加载 Wav2Lip，不与 ComfyUI 生成任务并发；VRAM 峰值继续受 NFR-02 `≤22GB` 约束。
- 原始 WAV、帧和 MP4 只写入 `.gitignore` 覆盖的 `audit/` 或用户私有目录；不提交真人素材。
- 网络仅允许 `127.0.0.1:8010`；验收脚本不得下载模型或上传内容。
- 验收结束关闭 WebSocket session，释放编码器、线程和临时容器文件。

## 出门效果

用户可看到一段由真实产品链路生成的“动态人物 + 实际 TTS + 实时嘴型”视频；报告能区分帧率、传输时钟、嘴部运动响应和人工自然度四类结论。任一自动化硬门失败均返回计划/修复阶段，不能用主观“看起来可以”覆盖。
