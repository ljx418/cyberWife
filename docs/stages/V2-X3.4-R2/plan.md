# V2-X3.4-R2 开发计划：口型末段闭环

## 目标

修复最后有效语音之后仍持续生成口型、嘴部抖动及验收视频超出有效音频区间的问题，同时保留 R1 已证明的构建期脸框稳定收益。

## 实施顺序

1. Avatar 对外部 PCM 做有界、可复现的低能量静音分类，并保留短静音释放窗口，避免单帧低能量误切 Idle。
2. 将批次级“任一帧有声则整批说话”改成逐视频帧状态选择：有声帧采用 MuseTalk 结果，静音帧采用原 Idle 帧；模型仍按批推理，不改变显存与吞吐结构。
3. 增加 generation 完成信号：Gateway 在正常 TTS/缓存播放结束后通知 Avatar，Avatar 立即补入一个静音排空批次；取消仍沿用 cancel，不混用 complete。
4. 修复采集器：发送完成信号，主 A/B 视频严格限制为输入 WAV 时长，不把额外 drain 伪装成有效口播。
5. 修复分析器：单独计算最后有效语音后的嘴部差异与时序运动，新增末段衰减硬门。
6. 用相同 8 秒真实 PCM 对三场景重新采集；完成单元、后端、Avatar、前端端到端回归。

## 不在范围

- 不更换 MuseTalk 模型或权重。
- 不降低 25 FPS、7 秒首响或 24 GiB 显存门槛。
- 不以裁掉异常片段替代产品链路修复；严格时长只用于防止验收工具额外制造伪尾段。
- 不启用像素 EMA、音频特征 EMA 或额外抠图层。

## 回滚

产品改动均受 PCM 状态和 complete 控制约束；移除 complete 调用并恢复外部 PCM 默认有声即可回到 R1。R1/R2 数据集使用独立证据目录，不覆盖正式红衣形象。
