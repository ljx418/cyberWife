# ADR-013：V2 先体验优化、后架构扩容

**状态**：ACCEPTED
**日期**：2026-10-06
**决策人**：项目所有者（明确批准 V2 分为体验交互优化和架构扩容，并先做体验优化）

## 背景

V1 已到人工总验收前。新增诉求同时包含两类变化：一类是多源图片、构图、背景、低幅 Idle 和记忆可视化等可直接改善沉浸感的体验；另一类是多形象、多空间、文件隔离、导入导出及 MCP/RAG/CLI 连接器，需要替换当前“单一活动人物”的领域假设。

如果先进行完整平台化，用户会长时间看不到体验收益；如果把所有能力堆入当前单例设置和 JSON，又会产生不可迁移的数据和安全债务。

## 备选方案

| 方案 | 得到 | 代价 | 决策 |
|---|---|---|---|
| A. 先完整架构迁移，再做体验 | 数据模型一次到位 | 体验收益延后；迁移面和回归风险同时最大 | 拒绝 |
| B. 先做一次性 UI/JSON，之后重写 | 短期可演示 | ID、授权、派生关系和路径规则不可迁移 | 拒绝 |
| C. 体验优先，但从第一天使用版本化清单和稳定 ID；随后登记为正式聚合 | 先获得体验，同时保留可迁移边界 | 需要维护短期兼容层和迁移测试 | **采用** |

## 决策

1. V2 划分为 `V2-X 体验交互优化` 与 `V2-A 架构扩容`，严格按 X→A 执行。
2. V2-X 保持一个活动角色上下文，不提供多角色管理假象；新增 source/appearance/scene 清单使用稳定 UUID、schema version、哈希、授权和来源。
3. V2-A 在模块化单体内新增 Character、Appearance、Space、ActiveContext 和 Memory Platform bounded context；不拆业务微服务。
4. 只有不可信插件执行进入低权限独立进程；SQLite 继续是本机权威写存储。
5. MCP、RAG、Codex/Claude CLI 通过防腐适配器返回候选或带来源的检索结果，默认不能直接写核心记忆。
6. V2-A 迁移必须能够从 V2-X 清单登记实体而不更换 ID，且支持事务回滚到 V1/V2-X 活动上下文。
7. V2-A为每个Character新增`AvatarModelPolicy`。用户可以在已经安装、具有同角色兼容rendition且通过质量门的引擎间选择；切换采用串行停旧启新和健康确认，禁止Wav2Lip/MuseTalk双常驻。引擎启动失败时不得提交新的`ActiveContext`。

## 影响

- 用户先获得多素材、场景、构图、低幅 Idle 和记忆工作台，不必等待平台化全部完成。
- V2-X 需要承担清单 schema、来源和迁移试验的前置成本，但避免一次性实现被推翻。
- V2-A 会修改数据库 schema、资产路径解析、活动上下文、API 和前端导航，必须独立执行迁移与组合回归。
- 当前 V1 的 TurnPipeline、取消代际、TTS/Avatar 端口和一键生命周期继续复用；V2 不得降低既有性能、隐私和资源门。
- 用户可以按角色选择质量/资源档，但每种外观与场景都需要对应引擎派生物；选择器不能把缺失工件的模型显示为可用。

## 回滚

- V2-X：清单与派生资产独立存放，关闭 feature flag 后恢复 V1 当前形象、背景和记忆列表。
- V2-A：迁移前生成 schema/资产清单备份；新表和新路径在事务提交后才切换 `ActiveContext`。失败时恢复旧单例指针，新增数据保留在隔离 staging 供诊断，不覆盖旧资产。
