# ADR-011：Avatar独立存活通道与媒体应用层心跳

## 状态

Accepted — 2026-10-04；用户批准同时实施路线1与路线2。补充ADR-010，不改变H.264/WebCodecs媒体方案。

## 背景

AC-06真实组合验收表明，Wav2Lip推理与`/health`共用aiohttp事件循环时，1～1.5秒HTTP或帧超时会把健康但繁忙的会话误判为故障，并引发`max_session=1`下的重连争抢。把门槛放宽到7秒会造成明显冻结，不满足已批准的2秒静态降级体验。

## 决策

- Avatar进程内新增一个独立daemon线程，以标准库`ThreadingHTTPServer`监听`127.0.0.1:8011`的`/healthz`。它不访问模型、渲染队列或用户内容；绑定失败时Avatar启动失败。
- H.264 WebSocket在连续500ms没有二进制帧时发送`avatar.heartbeat` JSON；任何合法二进制帧或应用心跳都刷新客户端媒体活性时间。
- 客户端媒体活性超过1200ms未刷新时，在最多500ms内探测独立控制通道：控制通道存活则仅清空canvas并进入软`static_fallback`，保留原WebSocket/decoder；控制通道不可达则硬降级并按既有退避同页重连。
- 心跳本身不恢复动态图。软降级后必须收到并成功解码真实视频帧才恢复`ready`，连接代次不增加；进程重启后的新连接恢复则连接代次增加。
- 8010与8011均只能绑定loopback；CORS仅允许批准的本机前端Origin。新增通道不发送音频、文本、路径或模型信息。

## 后果

2秒降级判定不再依赖繁忙的推理事件循环，同时媒体卡顿可在不争抢新session的情况下显示静态人物。成本是一条同进程独立线程和一类WS控制消息；无新增模型、进程、显存或持久化。若应用心跳不兼容，可独立关闭客户端watchdog并回到ADR-010断线恢复，控制端口也可随Avatar整体移除。

## 验证与退出门

- 单元测试证明控制服务仅loopback、Origin白名单、响应无敏感字段、停止后释放端口；心跳合同字段稳定。
- 真实Chrome与四个受管组件执行3个故障/恢复周期：每周期≤2秒进入静态降级，音频和文字继续，同页恢复且恢复轮媒体/服务端FPS≥25。
- 健康推理期间不得出现误重连或新session争抢；RAM≤14GiB、VRAM≤22GiB。
