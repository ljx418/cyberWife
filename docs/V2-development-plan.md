# cyberWife V2 开发与验收总计划

**版本**：1.0
**日期**：2026-10-06
**状态**：范围与顺序已获项目所有者批准；尚未进入 V2 代码开发
**权威关系**：本文件是 V2 阶段、依赖和验收门的唯一详细来源；PRD、项目计划和目标架构只保留摘要与回链。

## 1. 目标与阶段决策

V2 让本机数字伴侣从“单一当前人物的一套实时链路”演进为“可以沉浸布置、可以管理多个形象与空间、可以扩展记忆来源的本地平台”。V2 保持单用户、离线优先、32GB 物理内存/约 16GB 空闲内存、RTX 4090 24GB 的既有硬件边界，不以新增云服务、第二台电脑或多模型双常驻换取功能。

V2 固定划分为两个阶段，并严格按以下顺序执行：

```text
V1FINAL 与 V1 体验修补闭环
  └─ V2-X：体验交互优化（先执行）
       └─ G-V2X：真实素材体验、资源、隐私与迁移清单全绿
            └─ V2-A：架构扩容（后执行）
                 └─ G-V2A：多形象/多空间/插件记忆平台全绿
```

- **V2-X 体验交互优化**：先让用户获得多素材、全身构图、多背景、低幅 Idle 和可视化记忆工作台；仍只允许一个活动角色上下文，不提前引入多角色并发或插件执行宿主。
- **V2-A 架构扩容**：再把角色、外观、空间和记忆提供方提升为按 ID 管理的一等领域实体，完成路径隔离、导入导出、MCP/RAG/CLI 连接器和迁移回滚。
- V2-X 不得绕过 V1FINAL；V2-A 不得绕过 G-V2X。阶段编号不是并行开发授权。

## 2. 不变量与非目标

两个阶段共同遵守：

1. 核心对话继续使用现有 `TurnPipeline`、取消代际和 A/V 同步时钟；体验升级不得降低 V1 的首响、打断、连续对话、隐私和稳定性门。
2. 项目非可回收内存峰值仍不超过 14GB，VRAM 峰值仍不超过 22GB，宿主与 WSL 均保留至少 2GB；重型生成与实时对话不双常驻。
3. 真人素材必须保留授权、来源和派生关系；未批准的生成结果不得成为活动形象。
4. 原始麦克风音频不落盘；私有图片、视频、记忆正文、导出包不进入 Git。
5. 保持模块化单体。只有不可信插件执行需要隔离宿主；V2 不以微服务拆分为目标。
6. 不承诺从半身照可靠推断未出现的身体、服装或真实事实；系统必须标出“原图事实、用户确认、模型生成”三种来源。
7. V2 不包含多人在线、公网分享、云同步、移动端、自动发布内容或商业授权替换。

## 3. V1 到 V2 的入口基线

进入 V2-X 前必须同时满足：

- V1FINAL 现场报告绑定当前发布 revision，或项目所有者书面接受未关闭的人类主观项；
- V1 的 20 轮、30 次打断、1 小时稳态、删除零召回、no-record 零持久化和单机生命周期门仍有效；
- 完成 V1 低风险体验修补：极端窗口布局、本地背景库、低幅 Idle、记忆手工新增/候选确认，或逐项记录书面延期理由；
- 形成 V2 基线备份、数据库 schema 版本、资产清单和回滚点；
- 开放 P0/P1 为 0。

## 4. V2-X：体验交互优化

### 4.1 范围

| 工作包 | 用户得到的体验 | 实现边界 | 明确不做 |
|---|---|---|---|
| V2-X1 多源形象素材 | 一次导入正面、侧面、全身、不同穿着照片；逐张查看角度、服装和来源 | 一个活动角色下的 `source-pack` 清单；原图只读保存，派生图另存 | 多角色切换、任意人物混合训练 |
| V2-X2 沉浸式构图 | 头像、半身、全身三种构图；超高/超宽窗口有专用舞台 | 焦点、安全区和构图元数据驱动，不复制业务状态 | 在 180px 高窗口强行展示完整全身和所有控件 |
| V2-X3 外观与场景预设 | 为当前角色选择已确认的服装外观、背景和场景；切换时不中断会话状态 | 本地离线生成；`appearance-manifest`/`scene-manifest` 使用未来可迁移 UUID | 运行时任意文本换装、云端生成 |
| V2-X4 低幅 Idle | 轻微呼吸、眨眼、固定摄影机、低头肩位移、无缝循环 | 离线生成 + 机器运动门 + 每素材人工确认 | 用 Idle 视频替代说话口型验收 |
| V2-X5 图像理解交互 | 能基于已上传并由用户确认的外观描述谈论穿着、构图和场景 | 本地视觉描述生成候选；用户确认后才进入 Profile/Memory | 把模型猜测当成用户身体或身份事实 |
| V2-X6 记忆工作台 | 手工新增、候选确认、来源追踪、基本分组和可视化关系 | 继续使用内置 SQLite；图谱为只读派生视图，边均有来源 | MCP、外部 RAG 或 CLI 直接写核心记忆 |

### 4.2 前向兼容清单

V2-X 虽不启用完整多实体管理，但所有新增派生资产必须写版本化清单：

```text
source-pack.json
  schema_version, pack_id, consent_id, sources[]
  source: id, sha256, view, outfit_label, provenance, approved

appearance-manifest.json
  schema_version, appearance_id, source_pack_id, rendition_ids[]
  user_confirmed_description, generated_claims[], quality_gate

scene-manifest.json
  schema_version, scene_id, background_asset_id, focal_point
  safe_regions, overlay, provenance, quality_gate
```

`pack_id`、`appearance_id`、`scene_id` 从创建时即采用不可变 UUID。V2-A 迁移只能把清单登记为正式聚合，不能重新生成 ID 或把不同授权素材静默合并。

### 4.3 开发顺序

1. **V2-X0 合同与证据基线**：冻结 V1 指标、定义清单 schema、迁移试验和隐私扫描。
2. **V2-X1 多源形象素材**：原图保留、角度/服装标签、授权和派生链。
3. **V2-X2 沉浸式构图**：头像/半身/全身、焦点安全区和极端视口回归。
4. **V2-X3 外观与场景预设**：背景/外观、原子切换、失败回退和跨重启恢复。
5. **V2-X4 Idle 收敛**：固定摄影机、动作量化、首尾帧门和逐素材人工确认。
6. **V2-X5 图像理解交互**：候选描述、来源标识、用户确认和对话注入预算。
7. **V2-X6 记忆工作台**：手工记忆、候选、分类、只读图谱、来源与删除传播。
8. **V2-X7 组合回归**：真实多素材、实时对话、资源、隐私、恢复和一小时稳态。

每个子阶段必须先落盘 `plan.md`、`acceptance.md`、`pre-development-audit.md` 和 `prd-review.md`；开发后补 `result.md` 与 `acceptance-report.md`。存在新增致命或重大规格风险时不得进入下一子阶段。

## 5. V2-A：架构扩容

### 5.1 目标领域模型

```text
Character(id)
├─ Profile
├─ VoiceProfile
├─ AppearanceSet(id)
│  ├─ SourcePack(id)
│  └─ Rendition(id, engine, manifest)
└─ MemoryNamespace(id)

Space(id)
├─ BackgroundAsset(id)
├─ ScenePreset(id)
└─ LightingPreset(id)

ActiveContext(singleton per local user)
└─ character_id + appearance_id + space_id + rendition_id

MemoryPlatform
├─ CanonicalMemory + MemoryEdge + MemoryCluster
├─ MemoryProviderPort
├─ KnowledgeConnectorPort
└─ ToolBridgePort
```

活动上下文仍是单用户单会话唯一选择，但数据库不再把“只有一个 Character/Space”写死。切换必须在一个事务内校验授权、派生就绪状态和资源预算，然后原子更新 `ActiveContext`。

### 5.2 文件系统隔离

```text
data/
├─ characters/<character-id>/
│  ├─ profile.json
│  ├─ appearances/<appearance-id>/sources/
│  ├─ voices/
│  └─ memories/
├─ spaces/<space-id>/
│  ├─ manifest.json
│  └─ backgrounds/
├─ renditions/<rendition-id>/
└─ staging/<import-job-id>/
```

- 所有路径从经过验证的 ID 解析，API 不接受任意绝对路径。
- 导入先进入 `staging`，完成 schema、哈希、配额、授权和路径穿越检查后原子提升。
- 导出默认不包含模型权重、对话正文和外部提供方密钥；用户必须显式选择是否包含记忆。

### 5.3 记忆插件平台

V2-A 定义以下端口：

- `MemoryProviderPort`：`health/search/upsert/delete/export`；
- `KnowledgeConnectorPort`：`sync/query/provenance`；
- `ToolBridgePort`：受限调用 MCP、Codex CLI、Claude CLI 等工具；
- `ClusterProviderPort`：离线聚类并返回可解释标签、成员和版本。

内置 SQLite 是权威写存储。外部 llmwiki/RAG/MCP/CLI 默认只能返回带来源的候选或检索结果，不能直接写核心表。写入必须经过统一策略、用户授权、去重和审计。插件需声明能力、数据范围、超时、配额和网络需求；不可信插件由独立低权限进程托管，并有熔断与卸载回滚。

### 5.4 开发顺序

1. **A0 数据迁移**：新增 Character/Appearance/Space/ActiveContext schema；旧单例数据可重复、可回滚迁移。
2. **A1 多形象管理**：按 ID 新增、切换、归档；人物、声音、记忆命名空间严格绑定。
3. **A2 多空间管理**：空间 CRUD、背景/灯光预设和活动上下文原子切换。
4. **A3 导入导出**：版本化包、哈希、授权、配额、路径安全、冲突处理和回滚。
5. **A4 记忆模型扩展**：实体、关系、聚类、来源和命名空间；旧记忆无损迁移。
6. **A5 连接器端口**：内置 SQLite adapter、外部 RAG adapter、MCP bridge、CLI bridge。
7. **A6 插件隔离与组合回归**：低权限宿主、超时/熔断、隐私扫描、多角色多空间长稳态。

### 5.5 G-V2A 出门门

| ID | 用户场景与操作 | 硬门 |
|---|---|---|
| V2A-AC01 | 创建 3 个角色、每个 2 个外观并来回切换 | 100 次切换错误资产/声音/记忆串用为 0；切换失败保持旧上下文 |
| V2A-AC02 | 创建 3 个空间并为不同角色选择 | 角色与空间可独立组合；跨重启恢复同一活动上下文 |
| V2A-AC03 | 导出后在空数据根导入，再比较 | 清单/哈希/授权一致；默认无私密正文和密钥；回环等价率 100% |
| V2A-AC04 | 导入含 `../`、重复 ID、错误哈希和超配额包 | 全部拒绝且活动数据不变；staging 可清理 |
| V2A-AC05 | 接入一个本地 RAG 与一个 MCP/CLI 测试连接器 | 可启停、健康可见、超时可熔断；未经确认写核心记忆为 0 |

| V2A-AC07 | 运行多角色/多空间/内外部记忆组合一小时 | V1/V2-X体验、隐私和资源门无回退；P0/P1=0 |

## 6. 架构方案与取舍

| 方案 | 优点 | 代价/风险 | 决策 |
|---|---|---|---|
| 把多角色、空间和插件都塞进现有 settings JSON | 实现快 | 无事务边界、路径隔离和可迁移性；后续必然重写 | 拒绝，仅允许 V2-X 保存展示偏好 |
| 模块化单体中新增 Character/Space/Memory bounded context | 复用现有一致性、启动和本机调试；迁移可控 | Gateway 模块边界必须持续用 AST/合同测试约束 | **采用** |
| 立即拆成多微服务 | 独立部署和扩缩容 | 对单用户本机产品增加端口、资源与故障面 | 拒绝；仅隔离不可信插件宿主 |

本决策详见 [ADR-013](architecture/adr/ADR-013-v2-experience-first-expansion.md)。

## 7. 风险与停线条件

| 风险 | 触发信号 | 处置 |
|---|---|---|
| 身份/服装串位 | 人工或哈希关联发现错误人物、错误外观 | P0，停止激活并回滚派生资产 |
| 生成事实冒充真实事实 | 未确认身体/穿着描述写入 Profile/Memory | P1，关闭图像理解注入并清理派生记录 |
| 资源突破 | RAM/VRAM越既有门或生成与实时模型双常驻 | P1，序列化调度、卸载生成模型后重测 |
| 多实体串数据 | 角色间声音、记忆、图片泄漏 | P0，停止 V2-A，回滚 ActiveContext 迁移 |
| 插件越权/上传 | 未声明网络、越权路径或绕过候选确认 | P0，禁用插件宿主并审计全部访问 |
| 图谱伪关系 | 无来源的边或相似度被表述为事实 | P1，降级为分类列表，不允许出门 |
| V1体验回退 | 首响、打断、口型、长稳态任何硬门失败 | 返回对应子阶段，不得以 V2 新功能豁免 |

## 8. 文档和证据交付

每个 V2 阶段至少交付：

1. 原型/交互规格与真实基线截图；
2. 详细开发计划、PRD 追踪矩阵和阶段审计；
3. 目标/当前架构图及迁移、回滚数据流；
4. API、schema、文件清单和错误合同；
5. 单元、合同、集成、真实模型和 E2E 测试；
6. HTML 中文验收报告、截图/视频、JSON/JUnit/CSV 机器证据；
7. 隐私、路径、网络、资源和许可证审计；
8. 已知限制、人工验收项和下一阶段入口结论。

任何文档出现“用户场景、操作步骤、具体门槛”三项缺失之一，均不能作为阶段验收依据。
