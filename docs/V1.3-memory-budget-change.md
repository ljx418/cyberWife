# V1.3 内存预算变更

**日期**：2026-09-24  
**批准人**：项目用户  
**状态**：APPROVED

## 变更原因

目标机有 32GB 物理内存，但 Windows 静止、无额外负载时通常只有约 16GB 可用。参考体验攻略的公开硬件说明是“内存 16G 起步，32G 更稳”，不是“应用或 WSL 必须独占 28GB”；15G 指的是四模型显存组合。原合同把整机推荐内存错误转换成 WSL 最小配额，现予纠正。

## 新预算

- 目标机仍为 32GB 物理内存、RTX 4090 24GB。
- 启动前系统可用内存基线约 16GB；不要求修改 `.wslconfig`，接受当前 WSL 15.52GiB 上限。
- 项目非可回收内存（Windows项目进程private bytes + WSL项目进程RSS）峰值≤14GB，并为宿主和WSL各保留至少约2GB可用内存。
- 宿主`Available MBytes<2048`、WSL `MemAvailable<2GB`、发生持续swap-in或项目非可回收内存>14GB均判为资源压力，不得掩盖。
- SpeechRuntime 同一时刻只常驻交互阶段所需的 ASR 或 TTS 重模型；Embedding 按需加载后释放；LLM 保持 Windows mmap/GPU 路径；Avatar 不反向阻塞音频。
- Windows进程working set、private bytes和WSL进程RSS分别保存。硬门使用private bytes+RSS；GGUF mmap/file-backed working set单列观察且由宿主`Available MBytes`兜底，不与RSS机械相加，否则会把可回收页计成永久独占。
- 超预算时依次采用：释放 Embedding/缓存 → ASR/TTS 分时卸载 → 缩小 LLM KV/context → 降低非音频 Avatar 缓冲。仍超预算则阻止 V1 出门，不降低对话正确性、隐私或打断门槛。

## 不变项

P50/P95 首响、打断400ms、Avatar 25FPS、VRAM≤22GB、真实模型证据和离线隐私边界均不放宽。
