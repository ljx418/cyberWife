03 · TARGET ARCHITECTURE

一条主链，两个透明加速点

所有模块名都映射到后续代码责任。缓存只在 ASR final 后做严格白名单匹配；未命中立即进入正常 LLM→TTS，不允许等待缓存或改变回答边界。

已实现Browser Playback首个非静音样本才算首响；音频是口型主时钟。
需修改TurnPipeline统一 request_id / turn_id / generation；保留六态。
待新增WarmResponseCache内存≤64MiB；精确命中；版本变化立即失效。
需修改llama.cpp Profile单slot、prompt cache、实测后决定n-gram推测。
待新增TTS Runtime Port原生TRT优先；独立loopback worker；单后端常驻。
已有基础Avatar Adapter跟随音频时钟；迟到视频丢帧；故障静态降级。
普通未命中

ASR final → PromptCompiler → llama.cpp → 首个可播短句 → 加速TTS → 浏览器与Avatar。它独立承担 PRD P50/P95 门槛。

严格命中

ASR final → 精确白名单 → 已预热文本+PCM → 浏览器与Avatar。天气、带附加语义的问候、继续说均强制未命中。

参照 Radix UI 的 Tabs、Dialog、Switch 与 Tooltip 行为规范，但延续项目自己的颜色、字体和密度。选择路由查看组件职责；没有新增用户路由。

组件规则

命中必须比“看起来聪明”更克制

  • 仅规范化后的整句精确匹配；不做模糊匹配。
  • “你好，我今天很难过”必须进入正常模型。
  • 天气、记忆提问和“继续说”永远不缓存。
  • 声音、人设、模型或策略版本改变后立即失效。
  • 主屏不显示“缓存命中”；运行状态二级页可诊断。
